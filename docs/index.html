Gated Scale-aware Context Analysis Platform for Exploration:

An interactive research platform for multi-scale geospatial scene classification. GSCAPE explores how information from different spatial scales can improve scene recognition, allowing users to compare contextual views, examine learned fusion weights, and investigate model predictions.

    The views

    Three plates, one scene

    Each 1280 × 1280 px scene (1.28 km at 1.0 m/pixel) is cut into three nested, centered crops. Each crop is resized to 224 × 224 px, so the network sees equal pixel counts that cover very different amounts of ground. Flip the stage between Ground scale and Model input to see both.

    224 px input preview

    The model

    Light, gated

    One frozen MobileNetV2 reads each view. A gated fusion head learns how much each view's features should count. During training of the -VD heads, views are randomly switched off, so the head learns to cope with missing views.

    Limitations, stated plainly

    What this study cannot tell you

    • No coordinates in MEET. Geographic overlap between train, validation and test cannot be checked. Near-duplicates are screened only by exact MD5 and by feature cosine similarity to the nearest train sample.
    • UAE n is small. Up to 25 candidates per class, only classes with at least 5 accepted samples are evaluated, and some classes are not sampled at all (Dry field, Hills, Military training ground).
    • Sensor and date differences. UAE imagery is Copernicus Sentinel-2 at 10 m (winter 2025-26), ten times coarser than MEET, and five small-object classes cannot be sampled. There is no retraining or tuning on UAE.
    • B1 vs B2 is not a context comparison. The custom CNN is trained end to end on the center view and has a different architecture from the frozen-MobileNetV2 head.
    • Gates are weights, not explanations. A larger gate means the head leaned on that view's features, not that the view is causally important.
    • Grad-CAM is a visual aid. It shows where a class logit is sensitive, not a proof of what the model "understands".

      Method, data and credits
      How this was made
      
    
      
      
      Reproducibility
      
      
        
        
      • Subset: 24 classes sampled only from the official MEET split lists, never reshuffled. Per class and split: min(N, available), N = 200 train / 50 val / 100 test, seed 42.
        • 
        
      • Views are nested crops resized to 224 × 224 (bicubic in the export pipeline): center box (512,512,768,768), surround (256,256,1024,1024), global the full image.
        • 
        
      • Heads train on cached frozen MobileNetV2 (ImageNet) features. Seeds 42, 7 and 123 for every head; seed 42 for data and B1.
        • 
        
      • Tuning: keras-tuner RandomSearch, 10 trials each for B3-VD and B4-VD, macro-F1 on the whole validation set. Test and UAE never influence tuning.
        • 
        
      • Statistics: exact McNemar on paired test predictions (per seed) with effect sizes, and a bootstrap 95% CI on per-class context gain (test images resampled within each class, paired across models).
        • 
        
      • Pinned environment in requirements.txt and requirements.lock.txt. Run order in run_all.sh.
        • 
        
      • This site's browser preprocessing resamples with the browser canvas, which is not bit-identical to the export pipeline's bicubic resize. Only the head is parity-tested.
